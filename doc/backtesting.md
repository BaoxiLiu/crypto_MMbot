本文件是该主题的统一维护入口。项目总览见 [README](../README.md)。


## 做市实验配置与输出

### 默认实验

`config/experiments/default.json` 是正式三日筛选配置，不是历史复现模板：

| 项目 | 默认值 |
|---|---|
| 时间 | UTC `[2026-08-01,2026-08-04)`，上下文自7月30日开始，交易窗口外不计新交易 |
| 币种 | BTC、ETH、SOL、DOGE、SUI、UNI、LTC、CRV、XRP、WIF、1000PEPE、1000SHIB、1000BONK，均为USDC合约 |
| 策略 | paper_native_as v1：as_base、paper_s1_sc0两个参数配置；改进AS静态最低半价差1 tick，S1/SC0仍启用 |
| 费用 | maker仅0，taker 4 bp；资金费另行计入 |
| 队列与撮合 | 前后50%撤单假设、部分成交、已验证的本机makerfix2引擎 |
| 账户 | 每币独立600 USDC初始权益，1000 USDC敞口上限 |
| 延迟 | 行情发布后1.5 ms、计算100 μs、请求/回报各0.5 ms，均为配置假设 |
| 组数 | 13币 × 2策略配置 × 1费率 = 26组 |
| 输出 | 单文件HTML，final_only |

数量基线依据交易窗口开始前已可见参考价和交易所最小量规则计算；具体值见 `config/strategies/accounts/`，不能将600 USDC初始权益与1000 USDC敞口上限混为一谈。

### 入口与配置

```sh
python -B -m app backtest strategies
python -B -m app backtest validate-config
python -B -m app backtest prepare
python -B -m app backtest run --registration /准备命令返回的路径/registration.json
```

也可以 `python -B -m app backtest run` 直接按默认配置准备并运行。自定义实验使用 `--config config/experiments/你的配置.json`；解释器统一从本机 `paths.local.json` 读取，原始/认证行情根由 `QUANT_DATA_ROOT` 指定。输入校验不等于回测完成。

数据、策略、执行和报告配置分开：

- `config/datasets/`：已认证缓存、时间窗口和manifest哈希。
- `config/profiles/data/quick_inputs/`：默认实验的数据输入说明。
- `config/market/`：交易规则快照。
- `config/strategies/`：策略profile及按币账户/数量基线。
- 实验配置：选择币种、窗口、策略参数、费用、执行和输出。

同家族仅改参数，不复制策略实现。NH须提供覆盖全部币种的冻结模型；HJB使用v2。详细算法、出处及开关见 [doc/strategies.md](strategies.md)。新增策略比较必须保持数据、队列、延迟、账户和费率相同。

所有新回测都包含BTCUSDC、ETHUSDC，quick/full使用完整13币。自定义窗口必须先有匹配的认证数据；不得静默换日期、跳币或复用不匹配缓存。每次生成新run_id，不覆盖已有结果。`--max-segments`、`--max-files`仅用于明确标注的局部验证，不能作为完整窗口结果。

### 参数示例与已有结果比较

[AS模块配置](../config/experiments/as_s1_ablation.json)复用执行及风险profile，对比BTC/ETH的两个AS参数组合，共8组。正式运行不带局部限制；短验收可增加`--max-segments 1 --max-files 1`。示例结果仍经相同认证、worker、指标、HTML验证、发布、登记和清理流程。

```sh
python -B -m app backtest inspect-report --html /最终报告/report.html
python -B -m app backtest compare --html /实验A/report.html --html /实验B/report.html
```

compare返回已记录的标准指标，不重算，不生成另一套报告。仅支持完成的完整区间报告，核对数据/输入身份、窗口、币种、费用/延迟、账户、公共执行及指标源码；不同假设或局部范围拒绝标为配对结果。旧report-existing入口和分段比较器已删除。

局部CLI示例用于验证输入与输出链路；只覆盖上下文或零成交时不能视为完整交易验收。原生合成测试覆盖有效模拟成交、三家族冻结行为及新策略接入；正式收益结论需要新的完整区间实验。

### 数据与执行边界

报价使用决策时已可见盘口、成交和因子，Markout反馈只使用已到期样本。缺口处理、预热、有效覆盖和缺失指标按数据合同披露。归档L2重建的BBO不等同于独立bookTicker通道；队列50/50也只是撮合假设，不代表实盘真实排位。

输入文件、模型、配置与原生引擎身份在准备阶段校验并登记。不能修改哈希来放行算法或数据变化。费用与风险不允许由单个策略覆盖；强制保护、挂撤单回报和资金费使用公共执行层。期末残仓按最后可见价格估值，不假设已经平仓。

### 报告与清理

临时观测、源码身份与计算文件放 `data/experiments/.work/<run_id>/`。最终HTML验证、发布并登记成功后清理该工作区；失败发布有界诊断HTML并保留整个拥有标记的运行工作区（含成功组结果），待修复处理；不删除共享原始行情。轻量注册摘要在 `data/experiments/registry.json`，首次运行自动创建。

默认按三日筛选、全面评估分别汇总结果；新增策略只补跑新增组。既有结果直接读取最终HTML，不再从已清理的工作目录重新导出。HTML内嵌曲线、配置及身份，不依赖外部图片；需要单独报告时显式提出。

按实验显式配置的maker情景分别展示汇总、逐币对照和11类图表；默认仅maker 0，−0.3 bp不自动追加，同币同费率各策略共用坐标；币种选择联动所有图。净盈亏包含已实现/未实现盈亏、手续费与资金费；单位成交净收益=净盈亏/买卖合计成交额×10000。跨币先求和再相除，零成交与缺失指标不显示为0。具体口径唯一实现为 `src/metrics`，说明见 [RESULTS_GUIDE.md](backtesting.md)。

旧日期配置及独立52组编排器已删除。数据转换与认证仍使用专用数据工具；正式实验以默认实验配置、当前主线入口和 [AGENTS.md](../AGENTS.md) 为准。

## 结果分析与指标口径

默认窗口以[默认实验配置](../config/experiments/default.json)为准，为UTC 2026年8月1—3日。每图紧跟事实结论。以下列出指标定义与扩展边界，不表示全部扩展指标已实现；已有最终报告保持生成时合同。

### 先核对什么

核对 run_id、代码/数据/模型/配置、币种、UTC 半开区间、有效覆盖、连续方式、资金、估值、执行情景及费用。每币独立账户不等于共享保证金组合，组合必须从同步权益重算。

账本先对齐再评价：逐笔成交可重建持仓，手续费/返佣/资金费不重复；期末权益包含按指定价格估值的库存。权益变化已经包含未实现盈亏，不能再加一次。期末估值与有成本的强制退出是不同情景。

### 三种胜率

| 名称 | 定义和边界 |
|---|---|
| 信号方向正确率 | 有效预测和标签上的方向一致比例；中性带及被排除比例单列 |
| 成交后有利比例 | 有效 h 秒 Markout > 0 的成交数/有效标签成交数；明确锚点、加权和费用 |
| 闭合交易净胜率 | 按固定配对规则（建议 FIFO）的净盈利闭合片段数/全部可结算闭合片段数；零损益在分母，未平仓单列 |

盈利日比例另命名，不能与上面三者共用“胜率”。闭合片段容易受部分成交拆分影响，须同时给样本数、金额权重、平均盈亏和盈亏比。

### 报价、成交和未成交

分开记录决策、提交、接受、拒绝、部分/全部成交、撤单请求/确认及终止。cancel_request 不等于立即撤销；部分成交后撤单保留已成交部分。

当前标准报告已实现的是按全部提交新单CID分类的“全成、部分成、未观察到成交”，并保存订单生命周期原始记录；包含拒单、待确认和期末截尾，分母不是已接受订单，不能称真实最终成交概率。以下接受订单/截尾细分是进一步分析的目标口径，不代表当前柱图已经完成这种细分。

接受订单按“已终止零成交、已终止部分成交、全部成交、截尾零成交、截尾已有部分成交”互斥分类。窗口结束仍在挂单的是截尾，不能当最终零成交。任意成交率与全部成交率的分母注明是否为全部接受订单；已终止样本指标必须注明选择效应。

数量成交率按币分别计算；跨币若汇总，使用接受时参考价的固定名义权重。未成交等待不能填零；首次成交等待的条件分位数同时报告未成交和截尾比例。描述性“触价未成交”不证明真实队列位置，假想未成交机会不计入损益。

### 收益、风险与执行质量

| 指标 | 统一解释 |
|---|---|
| 净损益 | 实现损益 + 未实现变化 − 费用 + 返佣 + 带符号资金费及明确现金流；资金划转分开 |
| 区间收益 | 期末/期初权益 − 1；标明资本和实际区间，不以短期年化替代 |
| 日度 Sharpe | 连续 UTC 完整日超额收益均值/样本标准差 × sqrt(365)，ddof=1；无风险值显式配置；样本不足或零方差为 null |
| 最大回撤 | 固定权益网格相对历史峰值的最大下跌，注明比例/金额、网格、峰谷和恢复状态 |
| 当前融合实验换手 | 买卖实际成交名义额之和/初始资金；日均再除请求区间日历天数，当前为10天。不除2、不年化、缺口不外推；局部验证不填完整日均 |
| 时间加权权益换手（另命名） | 双边实际成交名义额/同期时间加权平均权益，属于另一分母合同；当前标准报告未输出，不与上述倍数混用 |
| 成交质量 | 成交价锚的有符号 Markout：s×(mid(t+h)−fill_price)/fill_price×10000；成交时 mid 锚另命名，不混用 |
| 库存风险 | 数量与名义敞口、时间加权暴露、极值、上限触发、残仓和资金不足 |
| 成本 | 手续费、返佣、资金费及退出成本分别列示，已经计入净损益的分项不重复相加 |

主 Sharpe 使用日收益，不能把秒级样本直接年化来制造大值；即使能计算也注明短窗口不稳定。无交易但估值完整的日期保留，行情缺失日不填零。当前融合实验Markout固定报告100ms、500ms、1s、5s、10s、30s、60s七期限，按本地处理成交回报起算，取到期后第一条可见mid，最大滞后250ms；旧实验保留其原时钟与期限。各组另报可用未来标签数和尾部截断；不是完整账户利润。

### 比较与报告

从 predictions → decisions → order_events → fills → ledger → equity 建立关联；统一指标生成表、Markdown/HTML 和 Dashboard，不能各自计算一套。旧实验缺字段时说明限制，不补造历史轨迹。

至少展示身份与限制、预测面板、订单漏斗、未成交/截尾、成交质量、权益/回撤/库存/成本、逐币逐日对照和复现命令。预测比较配对同样本键；策略比较保留同窗口所有回退和缺信号期间，不通过删时段美化结果。

统计区间按共同日历时间块处理跨币和时间依赖，给效应大小与样本日数，不把多币或多种子当独立证据。模拟队列、延迟假设、数据缺口与历史使用须明确。冻结实验仍使用其原合同指标；新分母或新估值规则产生新指标版本。

标准图文报告固定11节：PnL、回撤、每日成交额、换手、净仓位、发单成交、七期限Markout、Markout有效与删失样本、收益构成、每日数据覆盖、模块配对差值。具体文件与口径由根实验合同维护，此处不另设默认。

## 最终结果与空间管理

默认实验配置和策略组合示例默认 `outputs.format: html`、`outputs.retention: final_only`。

运行时，逐笔成交、Markout、权益数组、图表、汇总表、代码及参数快照写入 `data/experiments/.work/<run_id>/`。报告完成账本核对和来源校验后，将指标、逐日汇总、11张图及对应结论、完整配置和来源哈希内嵌为单文件HTML。图片不依赖网络或旁边的文件夹，报告可以单独移动、离线打开。

最终产物只有 `doc/reports/experiments/<run_id>/report.html`。公共 `index.html` 按实验、币种、策略、日期搜索；`experiments/registry.json` 保存轻量摘要及报告哈希。日期右端不含，局部运行与完整请求区间单列，完整回放仍须查看实际数据覆盖。

先校验HTML内嵌数据和全部图片，再发布报告、更新注册表，最后删除本次拥有标记的临时目录。共享行情、认证数据集和旧实验文件不在清理范围。运行异常会保存带有界日志摘要的失败HTML再清理；发布、校验或登记失败则保留临时目录，避免丢失唯一结果。进程被强行终止或磁盘写满时也可能留下临时目录。

默认关闭全量中间价和订单生命周期日志；订单提交仍暂存以计算成交率，七期限Markout仍在线计算。清理后不再支持直接重画逐笔图、重新分桶或从原成交文件复核，需按内嵌配置重新回放。后续研究流程若必须读取逐笔原始观测，应显式改为 `retention: all`；历史冻结配置未声明该字段时沿用all，不自动删除旧产物。

检查或提取HTML内嵌结果：

```bash
python -B -m app.backtesting.fusion_experiment inspect-report --html /绝对路径/report.html
```

若最终报告已生成但清理未完成，可对仍存在的临时登记恢复发布/清理：

```bash
python -B -m app.backtesting.fusion_experiment finalize-results --registration data/experiments/.work/<run_id>/registration.json
```

HTML只是展示和归档方式，不改变策略、撮合、资金费或指标口径。历史报告转HTML也不会重新运行回测。

## 回测资金费

当前实验按币种显式提供funding_manifest，读取和校验实现位于app/market_making/fusion/funding.py；结算由event_backtest及公共账户执行。旧project_current与独立funding_clock入口已删除。

结算现金流为 `−结算仓位 × markPrice × fundingRate`，使用官方记录的实际结算时刻与费率，不把预计费率当作结算值，也不假定所有币都是固定8小时结算。

模拟回放将资金费时点与订单/成交事件放在同一执行时序中；延迟和缺口处理以有效执行配置为准。缺口内沿用仓位属于明确假设，不能推断未知真实成交。

资金费计入公共账本和最终权益，报告中与成交收益、手续费及库存变化共同核对。末端持仓估值不等于已经执行平仓。

当前原生测试覆盖资金费和成交时序、跨段仓位及权益核对；不证明真实交易所的队列、滑点或私人订单延迟已校准。统一流程见[实验说明](backtesting.md)。


相邻独立片段的交易所时间可以不重叠，但前片段的迟到发布可能与后片段快照重叠。事件回放在没有自有订单的后片段初始化阶段推进到上一片段已处理的应用/账户时刻，再处理已到达输入并恢复决策；不得回拨应用时钟。每片段记录`monotonic_bootstrap_delay_ns`及实际开始时间，不制造重叠期成交，也不删除原始事件。
