## 因子库与项目的关系

因子库是做市研究主线的公共特征模块。它把已经可见的行情转换成盘口失衡、订单流、成交速度、收益波动、RSI等数值；这些数值可以进入模型，也可以直接进入策略规则。

```text
标准行情 ──→ 因子计算 ──→ 特征值 ──→ 模型预测（可选）
                                └──────────┬───────┘
                                           ↓
                                      策略生成报价
                                           ↓
                                    OMS / 队列与成交
                                           ↓
                                     成交、库存、权益
                                           ↓
                                    src/metrics / 研究分析
```

### 职责边界

| 部分 | 负责什么 | 当前入口 |
|---|---|---|
| 数据层 | 行情、事件时钟、断链、来源和认证 | `config/datasets`、`app/backtesting/datasets.py`及数据准备链 |
| 因子库 | 公式、参数、历史状态、特征值与缺失语义 | `app/factor_library`；通用50维研究特征在`app/prediction`，分钟/论文实现已在公共因子库 |
| 模型层 | 使用过去已观测特征拟合/输出预测 | `app/prediction`与显式研究模型；未来标签只用于训练评价 |
| 策略层 | 根据价格、库存、可选特征/预测生成价格、数量和减仓意图 | `app/market_making/strategies`，通过统一注册表接入Kernel |
| 执行层 | 发撤改单、队列/部分成交、账户风控、费用记账 | fusion OMS及hftbacktest回放 |
| 分析层 | 净PnL、净bp、换手、回撤、Markout与统计诊断 | `src/metrics`（统一收益与成交指标）；因子评价归tools/factors |

这张图表示职责，不表示所有模块已自动连线。新目录只登记元数据；数值计算仍调用原后端。现有预测与报价不会因为目录新增就自动使用全部因子。

原始AS可以直接使用现有价格/波动估计器与账户库存，无需依赖全部因子库。加入失衡、RSI等规则或模型时，才明确选择所需因子、冻结版本，并通过策略适配层读取。

### 使用

核心库仅依赖Python标准库。离线构建和门槛冻结依赖PyArrow；所有原始和派生数据放被Git忽略的data/，小型验收统计和代码可提交。

```bash
python3 -m unittest tools.tests.test_flow_factor_library -v
## 先用更早一小时固定门槛；其默认日期为09-30 00时
python tools/freeze_flow_quotas.py --symbols WIFUSDC BTCUSDC DOGEUSDC
python tools/build_flow_factors.py --seconds 3600 --symbols WIFUSDC BTCUSDC DOGEUSDC --params data/factor-library/flow-v1/parameters.json --out data/factor-library/flow-v1-hour
```

本次实际运行的13币门槛与结果在data/factor-library/；工具可通过--symbols选择币对。建模读取输出Parquet，保持received_ns为int64，与旧50因子基线以共同可见时钟/相同决策行重新对齐，不能直接把旧交易时间网格与新接收时间网格按相同整数强行拼接。库接受snapshot(t,levels,last_id)、update(t,完整levels,U,u,pu)、trade(t,p,q,is_buyer_maker,id)、query(t)。levels为(side,price,绝对数量)列表；t均为整数纳秒。应用同一消息中间不查询。

事件保留60s且总数≤200000；状态越界立即失效报错，不默默截断历史。查询是有界事件扫描，不声称O(1)；实时上线前需在目标币对负载验证p99成本。样本回放计时不含读取、分组和排序，不等于线上处理延迟。近端距离使用消息前最优价≤2个观测网格；工程工具根据快照价格差GCD推导观测网格，不等于交易所历史tick过滤器保证，正式采用要提供历史合约规则。跨来源消息率不能直接混训。

## 新增16因子：第一轮预测评测结果

2026-10-13完成。结论：近端挂单净流是当前最值得继续验证的一组；量时钟更像活跃度/波动风险描述，不是已经认证的订单毒性概率。所有因子保持研究状态，未接入线上、未推GitHub。

### 样本和公平对照

13币、16日、每日固定UTC01:00–02:00，共208个币小时、416个原文件，拒绝小时0。训练09-19至24日273780行；验证09-25至27日136890行；测试09-28至10-04日319410行。Q参数严格使用09-18更早数据，训练参数源的成交ID与接收时间均无断链/回退。完整小时为半开区间，首60s暖机剔除、末30s标签purge；非完整标签窗口不补齐。

旧50缓存的交易所时钟与S因子的接收时钟不一致，本轮重建了8个同接收时钟基础控制和相同币对one-hot，**不是原50因子的增量证明**。两目标是未来5s中间价收益和30s波动率，非条件成交后Markout。固定树模型、不调参；原生缺失分支，不将未知补0。协议：[PROTOCOL](models.md)；源码tools/evaluate_flow_factors.py。

波动目标主结果约1.164%改善，但缺失分支的贡献必须区分。后验诊断仅添加16个缺失指示、不添加因子数值，就改善约0.897%；方向目标缺失指示改善约-0.005%。这些是不同拟合模型，不能简单相减或算比例声称分解了贡献；至少说明不能把波动目标的全部提升归功于因子数值。
